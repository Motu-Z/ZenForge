## 2. 经验与排雷记录（踩过的坑）

| 坑 | 现象 | 根因 | 正确思路 |
|---|------|------|----------|
| **忙等自旋（后台高占用真凶）** | 打开进程页后切走 / 收托盘，CPU 仍满核 | 采样唤醒用 `ManualResetEventSlim`，只 `Set` 不 `Reset` → 信号永久置位 → `WaitAny` 立即返回无限自旋 | 改用 `AutoResetEvent`（一次 `Set` 只唤醒一个）；无人观察时**同时**等「立即采样」信号与 `token.WaitHandle`，避免请求被丢弃；`ReleaseWatch` 不再 `Reset()`（AutoReset 自动复位） |
| **`Page` 父级崩溃 + 日志风暴** | 启动即卡死，日志几秒破 500MB | `Page` 只能由 `Window`/`Frame` 承载，路由把它塞进 `ContentControl` → `OnVisualParentChanged` 每次布局抛 `InvalidOperationException` → 兜底写完整栈 → 暴涨 | 7 个页面全部转 `UserControl`；`NavigationRouter` 注释明确「页面必须是 UserControl，不能是 Page」 |
| **全局异常无上限** | 一次布局风暴写出几百兆日志 | 全局异常处理无条件写完整栈 | 同签名限流（前 3 次完整栈，之后每 500 次补一行计数）；域/任务未观察异常外层加 try-catch 防二次风暴 |
| **侧栏七图标整片不显示** | 编译 0 警告，图标全空 | `Path` 无 `Foreground` 属性，`RelativeSource=Self` 绑定静默失败 → `Stroke=null` | 改绑所在 `ToggleButton.Foreground` |
| **Pill 选中态底/字同源翻暗** | 选中后底与字一起变暗，文字看不清 | `Bd.Background` 与 `IsChecked` 文字色同源绑 `Foreground` | 拆两层：底取 `Foreground`，文字单独 `TextBlock.Foreground` |
| **虚拟化选中色乱飘** | 滚动后选中高亮跳到别的行 | 命令式硬改 `Background`，容器复用后状态错位 | `DataTrigger` 绑定容器 `IsSelected` 驱动，停止代码改背景 |
| **列表刷新闪烁 / 滚动弹顶** | 每次刷新整列闪、滚动回顶部 | `Clear()` + `Add` 触发 `Reset` 通知 → 重建全部可视容器 | 增量比对 `Move`/`Insert`/`Remove`；`SameEntries` 未变更不发通知；后台 / 非当前页挂起刷新 |
| **WMI 降级轮询隐藏时不挂起** | 收托盘仍每秒枚举进程 | 降级全量轮询分支没有可见性闸门 | 隐藏时 `await Task.Delay(...)` 挂起；**WMI 事件模式刻意保留**（OS 进程创建事件、闲时成本≈0，是后台调度命脉） |

## 3. 核心约束与红线（绝对禁止）

1. **禁止 `Clear()` 重建列表**：必须用 `ObservableCollection.Move` / `Insert` / `Remove` 增量比对；内容未变用 `SameEntries` 短路，一条通知都不发。
2. **列表必须开虚拟化**：`VirtualizingStackPanel` / `VirtualizingPanel`，否则数百控件一次性实例化 → 内存暴涨。
3. **虚拟化行状态必须数据驱动**：选中色 / 行背景**禁止代码硬改**，必须 `DataTrigger` 绑定 `IsSelected`。
4. **跨线程更新集合必须回 UI 线程**：`ObservableCollection` 改动一律 `Dispatcher.BeginInvoke`（采样线程、WMI 回调、计时器都在后台线程）。
5. **`ControlTemplate` 内禁止 `StaticResource` 跨字典引用 `App.xaml` 资源**（运行期崩溃）→ 改用 `DynamicResource` 或内联。
6. **路由页面必须是 `UserControl`，绝不能是 `Page`**（`Page` 只能由 `Window`/`Frame` 承载）。
7. **禁止写死颜色**：统一走 `ThemeService` 档位——普通 `SecondaryButtonStyle` / 主 `PrimaryButtonStyle`、强调色淡底 `AccentSoftHoverBrush`(25%) / `AccentSoftPressedBrush`(35%)、`Button.Neutral.Background`(#2A2A2D)；语义色 `Info#A3B8CC` / `Warn#F5D90A` / `Error#FF453A` 铁律，禁止被主题色覆盖。
8. **后台零占用硬约束**：`Window.Hide()` / 最小化 / 收托盘 / 切页时，经 `PageTimerManager` 挂起所有定时器，并经 `host-visible` 硬闸门停采样线程、挂起 WMI 降级轮询；**事件模式保留**。
9. **全局异常必须限流**，不得无条件写完整栈；未观察异常外层 try-catch，防日志风暴。
10. **文本极简禁废话**（机制说明一律进 README）；**0 警告 0 错误**；三层 SRP（见模块 5）。

## 5. 核心项目原则

- **技术栈**：WPF / **.NET 10**，C# 原生重绘外壳（无第三方 UI 库）；可在 Linux 用 `EnableWindowsTargeting` 做 Release 真编译验证（0 Error 0 Warning）。
- **工程路径与状态**：`/workspace/projects/ZenForge`，git 仓库，分支 `main`，当前 tag `v1.0.3`，工作树干净。
- **三层职责分离（SRP）**：
  - **Service 层**：业务逻辑（SMU 读写、注册表、进程采样、WMI）。
  - **Helper 层**：纯静态工具类。
  - **UI 层（Code-Behind）**：只做事件路由，**严禁**写入硬件交互或复杂计算。
- **编译要求**：提交前必须 **0 警告、0 错误**。
- **极简克制**：界面禁任何说明性废话；功能机制查 `README.md`。
- **基石效应**：每版改动必须为下版打地基，不返工。
- **版本号**：SemVer + 阶段标识——正式版无后缀、`-canX`（金丝雀）、`-preX`（预览）、`-fixX`（热修）；`Version` / `FileVersion` / `AssemblyVersion` 必须同步改。
- **规范文档（必读，位于 `docs/`）**：
  - `UI-设计规范.md`：色彩、字号阶梯、控件尺寸、页面布局、WPF 红线。
  - `项目规范与开发手册.md`：定位、SRP、注释、版本与路线图、UI 明细。
  - `CHANGELOG.md`：各版本 Fixed/Changed/Added（**以它为事实源**）。
  - `README.md`：面向用户的功能机制说明。
- **项目网盘（Project Drive）**：`/tmp/nd/files/`，最新源码与规范归档应同步至此（当前该目录为 10-29 旧快照，已用 v1.0.3 归档覆盖）。
