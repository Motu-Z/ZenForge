# 📚 ZenForge 项目规范与开发手册 (v1.0.2)

---

## 一、项目定位与核心原则

**项目定位**：一个极简、纯粹、完全本地运行的 AMD Ryzen 处理器调校工具（基于 WPF / .NET 10）。

**基石效应**：每个版本的改动必须为下一个版本打地基。遵循"先定 UI 骨架 → 再做动画 → 再填功能 → 最后写全局重置"的顺序，严禁因重构导致底层逻辑返工。

**极简克制**：界面应保持绝对干净，禁止出现任何说明性废话文字（如"当前电源方案支持……"）。用户想了解功能机制应自行查阅 README。

## 二、代码质量与防屎山规范（工程底线）

为了确保项目在持续迭代中不沦为屎山，所有代码提交必须遵守以下规范：

### 单一职责 (SRP)
- **Service 层**只包含业务逻辑（如 SMU 读写、注册表操作）。
- **Helper 层**只放纯静态工具类。
- **UI 层（Code-Behind）**只做事件路由，严禁将硬件交互或复杂计算写在 UI 文件中。

### 逻辑复用
相同的 UI 状态判断或格式化代码出现 3 次以上，必须提取为公共方法或 `Converter`。

### 注释规范
- 禁止写解释代码字面意思的废话注释（如 `// 关闭窗口`、`// 遍历列表`）。
- 必须保留解释"为什么这么做"的底层原理注释（如 `// 必须先开启事件再绑定，否则会漏掉第一帧`）。

### 死代码清理
重构时必须清除未引用的私有方法、无用的变量以及冗余的 `using`。

### 编译要求
任何提交前，必须保证代码 **0 警告、0 错误**。

## 三、版本管理与迭代路线

### 3.1 版本号规范 (SemVer 实践)

版本号必须遵循 `主版本号.次版本号.修订号-阶段标识` 的格式：

| 类型 | 示例 | 含义 |
|---|---|---|
| 正式稳定版 | `v1.0.2` | 无后缀，功能完整，经全量测试 |
| 金丝雀版 `-canX` | `v1.0.2-can1` | 大规模 UI 重构或底层架构重写时，极度不稳定，仅限内部自测 |
| 预览版 `-preX` | `v1.0.2-pre1` | 核心功能已跑通，正在修微小 Bug，交由极客用户尝鲜 |
| 热修版 `-fixX` | `v1.0.2-fix1` | 针对已发布正式版的单点严重 Bug 紧急修复 |

### 3.2 迭代路线图

| 版本 | 主题 | 内容 |
|---|---|---|
| **v1.0.2**（当前） | UI 定型与骨架重构 | 落实无边框窗口、7 项侧边栏、修复后台定时器空转 |
| **v1.0.3** | 表现打磨 | 进程列表平滑排序动画、高 DPI 字体适配、彻底解决日志内存积压 |
| **v1.1.x** | 功能注入 | 多方案保存切换、场景自动切换等未接入功能实装 |
| **v1.3.x** | 安全兜底 | 全局异常拦截、彻底清理所有数据与硬件的"真·重置" |

## 四、UI 视觉与规范

### 4.1 色彩体系

**基础背景**：窗口底 `#121214`，侧栏底 `#18181A`，卡片底 `#08FFFFFF`（半透明叠加）。

**强调色**：`#38BDF8`（仅用于边框、开关开启态、滑块填充）。

**语义色（铁律，严禁被主题色覆盖）**：

| 语义 | 色值 |
|---|---|
| 信息 Info | `#A3B8CC` |
| 警告 Warn | `#F5D90A` |
| 错误 Error | `#FF453A` |
| 危险按钮 | 边框与文字使用 Error 红 |

### 4.2 字体与间距

- **全局字体**：`Microsoft YaHei UI`；核心数值（如 140W、-18）使用 `Consolas` 等宽字体。
- **字号阶梯**：页面大标题 26px / 卡片标题 15px / 正文标签 13px / 说明文字 12px。
- **间距规范**：卡片内边距统一 `20, 22`，卡片间距统一 `16px`。

### 4.3 交互与动效

- 所有按钮、开关、下拉框、滑块必须包含平滑的 **Hover**（悬停提亮）和 **Active**（按压微缩）动效。
- 禁止使用系统默认的虚线焦点框（通过样式 `FocusVisualStyle="{x:Null}"` 强制干掉）。
- 列表类控件禁止全量刷新，必须开启 `VirtualizingPanel` 虚拟化回收。

## 五、页面布局明细清单

### 5.1 全局框架

**无边框窗口**：顶部保留 40px 拖拽区；右上角放置自定义的最小化、最大化、关闭按钮。

**侧边栏（208px）**：
- 分三组，组间用大 Margin（20px+）的分割线隔开。
- 包含 7 个导航项（带 16×16 矢量图标）：调校、进程、配置、通用、行为、高级、日志。
- 底部：左右分列 `中 / EN` 语言切换 和 当前版本号。

### 5.2 调校页
- **CPU 卡片**：左侧 CPU 名称与副标题，右侧四个按钮（加载/保存/刷新/应用全部）。
- **CO 网格**：自适应核心数的输入框，8 列等宽排列。
- **FMax 卡片**：标题位于左侧，输入框和单位位于右侧同一水平行。
- **电源与策略**：包含三个控件（电源策略下拉、升频模式下拉、核心停放滑块+输入框）。

### 5.3 进程页
- **运行中进程**：表头与内容列宽比例严格锁定 `3:7`，行内包含掩码与优先级下拉框。
- **已保存规则**：包含数量 Pill 徽章，底部的三个操作按钮（禁用/应用/删除）必须在一行显示（禁止换行）。

### 5.4 配置页
- **场景自动切换**：标题加右侧开关。
- **总体配置方案**：列表展示方案及描述，支持一键切换。
- **规则库双列**：左（调校规则）右（调度规则）并排，两卡片高度强制一致。

### 5.5 通用页
- **样式卡片**：主题模式下拉、强调色下拉、自定义颜色区（色块+彩虹滑块+HEX 输入框）。
- **诊断卡片**：导出日志按钮、SMU 自检按钮。
- **关于卡片**：居中展示版本号、开源协议（MIT）、GitHub 链接。

### 5.6 行为页
- **【启动】卡片**：开机静默自启（开关）、自动应用调校（开关）。
- **【后台】卡片**：开启后台服务（总闸），下方缩进展示子选项（常驻调度、轻量模式、托盘图标）。
- **【通知】卡片**：出错时通知我（放在页面最底部）。

### 5.7 高级页
- **【安全】卡片**：设备防砖保护、智能休眠感知（开关）。
- **【重置】卡片**：停用全部功能、清除全部数据（使用红色危险边框按钮）。

### 5.8 日志页
- **第一行**：带实心圆点的 Pill 标签（信息 165、警告 4、错误 0），右侧放置"详细日志"开关。
- **第二行**：搜索框，右侧放置"暂停"、"清空"、"目录"按钮。
- **日志列表**：左侧带对应语义颜色的竖线，元数据（时间）灰显。

## 六、WPF 底层工程约束（防崩溃红线）

1. **UI 线程调度**：跨线程更新 `ObservableCollection` 必须通过 `Dispatcher.BeginInvoke` 切回主线程。
2. **零后台空转**：建立 `PageTimerManager`，当窗口隐藏或切换至非相关页面时，强制 `Stop` 对应的定时器，确保后台纯待机时 CPU 占用为 0%。
3. **资源查找约束**：`ControlTemplate` 内严禁使用 `StaticResource` 跨字典引用 `App.xaml` 的资源，必须改用 `DynamicResource` 或内联。
4. **行状态数据绑定**：在开启虚拟化回收的列表中，行背景/选中色绝对禁止用命令式代码修改，必须通过 `DataTrigger` 绑定 `IsSelected` 属性驱动。
5. **列表刷新机制**：严禁 `Clear()` 后重建整个列表，必须使用 `ObservableCollection` 的 `Move`、`Insert`、`Remove` 进行增量比对更新。
